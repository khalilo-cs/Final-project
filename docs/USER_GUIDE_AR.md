# دليل المستخدم — مِحَكّ

دليل مختصر لكل دور. الواجهة عربية، ويمكن التبديل إلى الإنجليزية بزر **English** أعلى الصفحة.

---

## أولاً: الطالب

### الدخول
- **بحساب الجامعة**: زر «الدخول عبر حساب الجامعة» إن كانت الجامعة فعّلته، أو اسم المستخدم وكلمة مرور الجامعة نفسها (LDAP).
- **بحساب جديد**: تبويب «حساب طالب جديد».

### تسليم مشروع
1. من «مشاريعي» → **تسليم مشروع جديد**.
2. اكتب العنوان واختر المادة.
3. أرفق **الكود (ZIP)**، أو ضع **رابط مستودع Git** على GitHub أو GitLab أو Bitbucket أو Codeberg. الرابط يحفظ تاريخ commits، وهو يحسب لصالحك في الأصالة.
4. اختياري: التقرير (PDF/DOCX)، وقاعدة البيانات (ملف SQL أو تصدير MongoDB بصيغة JSON) مع اختيار نوعها.
5. **تسليم وتحليل**.

> **الإنترنت ضعيف أو انقطعت الكهرباء؟** الرفع يتم على أجزاء. إن توقف، أعد اختيار الملف نفسه فيكمل من حيث توقف ولا يبدأ من الصفر.

### بعد التحليل
- **نتائج التحليل**: جودة الكود، الثغرات الأمنية، قاعدة البيانات، التقرير، والأداء مع لقطات من واجهة مشروعك وهو يعمل.
- **المستشار الذكي**: نقاط القوة والضعف وما يمكن تطويره.
- **الإصلاحات المقترحة**: لا يتغير شيء في كودك إلا بموافقتك. تبقى نسخة الكود الأصلية محفوظة ويمكنك تنزيلها.

### المناقشة الذكية
- **ابدأ المناقشة الذكية** من صفحة المشروع. الأسئلة مولّدة من كودك، ويُعرض بجانب السؤال الكود المقصود بأرقام أسطره الحقيقية.
- يمكنك الإجابة كتابةً أو بصوتك (🎤)، ويمكن قراءة الأسئلة بصوت (🔊).
- إن انقطع الاتصال تُحفظ إجابتك ويتوقف الوقت، ثم تُرسل الإجابة تلقائياً عند عودة الاتصال.

### بصمة الفهم
اختبار قصير تُعرض فيه دوال من مشروعك وقد غُيّر في كل منها رمز واحد. حدد السطر المتغيّر وأعده كما كان، واشرح أثر التغيير. المحاولة واحدة فقط، فأجب دون الرجوع إلى ملفاتك.

## ثانياً: الدكتور

### إنشاء مادة
من **لوحة التحكم** → «المواد» → **إضافة مادة**. حدد:
- **مستوى الطلاب**: من السنة الأولى حتى الدراسات العليا.
- **نوع العمل**: واجب، أو مشروع مادة، أو مشروع تخرج.

هذان يضبطان تلقائياً أوزان التقييم، وطول المناقشة وصعوبتها، ووقت بصمة الفهم.

### إدارة المادة
- **إضافة طالب** باسم المستخدم.
- **أوزان التقييم**: عدّلها يدوياً. أو اضغط **اقترح من درجاتي** بعد اعتماد 5 مشاريع على الأقل، فيقترح النظام أوزاناً تطابق درجاتك المعتمدة، ويعرض متوسط الفرق قبل الاقتراح وبعده.
- **مقارنة الطلاب**: رسم بياني بالدرجة الكلية أو بأي معيار، ومعه خط متوسط المادة.
- **تقارير PDF للجميع** و**تصدير Excel**.

### لوحة التحكم
- **تصفية** حسب المادة أو الدفعة أو نوع العمل.
- **التنبيهات**: ثغرات حرجة، أو مشاريع لا تعمل، أو تشابه، أو **مجموعة نسخ** (3 مشاريع أو أكثر مترابطة بالتشابه، أي مصدر واحد تداوله عدة طلاب).

### صفحة المشروع
- **الدرجة المقترحة** مع تبرير كل معيار. **الدرجة النهائية قرارك**: عدّل ثم اضغط «اعتماد الدرجة».
- **أصالة المشروع**: تراها أنت فقط، والطالب لا يراها. فيها المشاريع المتشابهة، والكود المعاد صياغته، وتاريخ Git، وأسلوب الكتابة، ونتيجة بصمة الفهم.
- **مراجعة المناقشة**: صحّح تقييم أي إجابة، فيتعلم النظام من تصحيحاتك.

> مؤشر الأصالة قرينة وليس حكماً. استمع إلى الطالب قبل أي قرار، وتذكّر أن أول من سلّم ليس بالضرورة صاحب العمل.

## ثالثاً: مدير النظام

| المهمة | أين |
|---|---|
| إنشاء حسابات الدكاترة وتغيير الأدوار وحذف الحسابات | `POST /api/v1/users` و`PUT/DELETE /api/v1/users/{id}`. لا يمكن حذف آخر مدير ولا سحب صلاحياته. |
| ربط حسابات الجامعة | متغيرات `OIDC_*` (Microsoft 365 / Google) أو `LDAP_*` (Active Directory) في `.env` |
| سجل العمليات (Audit Log) | `GET /api/v1/audit` في خدمتَي المشاريع والمصادقة: من فعل ماذا ومتى ومن أي عنوان |
| حالة النظام | `GET /api/v1/dashboard/admin/stats`: المشاريع وطابور التحليل والأخطاء خلال 24 ساعة |
| النسخ الاحتياطي والاسترجاع | تلقائي يومياً؛ راجع [`tools/backup/README.md`](../tools/backup/README.md) |
| HTTPS | ضع الشهادة في `certs/` ثم شغّل `docker compose -f docker-compose.yml -f docker-compose.tls.yml up -d` |
| تشفير ملفات الطلاب | `STORAGE_ENCRYPTION_KEY` في `.env`، واحفظ نسخة منه خارج الخادم |

### التشغيل لأول مرة

```sh
cp .env.example .env      # عدّل كلمات المرور والمفاتيح
docker compose up -d --build
# الواجهة: http://localhost:8080
```
