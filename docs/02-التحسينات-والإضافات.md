# التحسينات والإضافات المقترحة لتكامل المشروع

هذه الوثيقة تكمل وثيقة المشروع الأساسية (`01-وثيقة-المشروع.md`) بمزايا وتحسينات إضافية موزعة على الطبقات الأربع، مع طبقات جديدة (التعليم، الجودة الهندسية، الأمان، إتاحة الوصول)، وترتيب أولويات واضح حتى لا تتضخم الخطة.

---

## 1. إضافات النواة اللغوية

### 1.1 نظام أكواد أخطاء موثَّق (على طريقة Rust)

كل خطأ يصدره المترجم يحمل كودًا فريدًا (مثل `عر-0012: لا يمكن جمع نص مع عدد`) مع **صفحة توثيق عربية** لكل كود تشرح السبب وأمثلة إصلاح. الفائدة مزدوجة:

- تجربة مطور أفضل حتى بدون إنترنت أو LLM.
- فهرس الأخطاء يصبح **قاعدة معرفة لطبقة الذكاء الاصطناعي** (انظر 3.1)، فيُغذّى الشارح بالصفحة الرسمية للكود بدل الاعتماد على معرفة النموذج العامة — وهذا يقلل الهلوسة قياسيًا.

### 1.2 REPL تفاعلي عربي

حلقة «اقرأ–نفّذ–اطبع» في الطرفية وفي المتصفح. تكلفته منخفضة (المفسر موجود أصلًا) وأثره في العرض أمام اللجنة كبير: تجربة فورية بلا ملفات.

### 1.3 سياسة Unicode صريحة للمعرفات (قرار تصميمي يستحق قسمًا في التقرير)

- **تطبيع NFC** لجميع المعرفات قبل المقارنة (فالحرف المركّب والمفكك يجب أن يكونا نفس المتغير).
- **سياسة التشكيل:** تجاهل الحركات في المعرفات (أو رفضها بتحذير) حتى لا يصبح «عَدد» و«عدد» متغيرين مختلفين.
- **توثيق قرار الألف/الهمزة:** هل «اسم» و«إسم» معرفان مختلفان؟ (التوصية: مختلفان، مع تحذير Linter عند التشابه).
- **منع خلط محارف مربكة** (حماية من homoglyph confusion) — نقطة أصالة بحثية قلّما تعالجها اللغات العربية القائمة.

### 1.4 مكتبة قياسية عربية مصغّرة

وحدات أساسية بأسماء عربية: `رياضيات`، `نص`، `قائمة`، `قاموس`، `وقت`، `عشوائي`. بدونها تبقى اللغة «مثالًا» لا أداة. تُكتب جزئيًا باللغة نفسها (dogfooding) — حجة قوية على نضج اللغة.

### 1.5 دمج النصوص (String Interpolation) ورسائل عربية طبيعية

صيغة مثل: `اطبع("مرحبًا يا ${اسم}")` — ميزة صغيرة تجعل الأمثلة التعليمية أنظف بكثير.

### 1.6 وضع الكلمات المفتاحية الثنائي (اختياري)

`aliases` إنجليزية للكلمات المفتاحية تُفعَّل بخيار للمترجم، لتسهيل الانتقال التدريجي من/إلى اللغات العالمية. تُسوَّق للجنة كـ«جسر تعليمي» لا كتنازل عن العربية.

### 1.7 اختبارات مدمجة في اللغة

بنية `اختبر "وصف" { تأكد(...) }` تُشغَّل بأمر `عر اختبر`. تعلّم الطلاب ثقافة الاختبار من اليوم الأول، وتُستخدم داخليًا لاختبار المكتبة القياسية.

## 2. إضافات أدوات المطور

### 2.1 منسّق كود تلقائي (Formatter)

`عر نسّق` يعيد تنسيق الملف بأسلوب قياسي واحد (مثل gofmt/Prettier). يُبنى فوق شجرة Tree-sitter الموجودة أصلًا، فتكلفته معقولة وفائدته ظاهرة في أي عرض حي.

### 2.2 مدقق أسلوبي (Linter)

قواعد بسيطة: متغير غير مستخدم، تظليل متغير، معرفات متشابهة بصريًا (من 1.3)، أقواس ناقصة شائعة. يُسلَّم عبر LSP نفسه كـ diagnostics من فئة «تحذير».

### 2.3 منقّح أخطاء عبر بروتوكول DAP (طموح/اختياري)

كما أن LSP يوحّد أدوات اللغة، فإن **Debug Adapter Protocol** يوحّد التنقيح. تنفيذ أدنى حد (نقاط توقف + عرض قيم المتغيرات خطوة بخطوة فوق المفسر) يرفع المشروع فوق أي مشروع لغة عربي سابق. إن ضاق الوقت: يُستبدل بـ«متتبّع تنفيذ مرئي» في محرر الويب (انظر 4.2).

### 2.4 ساحة تجريب (Playground) بروابط مشاركة

محرر الويب يضيف زر «مشاركة» يولّد رابطًا دائمًا (الكود مضغوط في الـ URL أو في تخزين بسيط). أثر عملي: أي طالب يرسل كوده لزميله أو لمشرفه برابط — وأي عضو لجنة يجرب المنصة من هاتفه عبر **رمز QR** أثناء المناقشة.

### 2.5 حزمة VS Code كاملة

إلى جانب LSP: تلوين صياغة عبر استعلامات Tree-sitter، أيقونة لملفات `.عر`، قوالب مقتطفات (snippets) عربية. تُنشر على Marketplace — «منتج منشور» نقطة قوية في التقرير.

## 3. إضافات طبقة الذكاء الاصطناعي

### 3.1 شرح مرتكز على التوثيق (RAG) بدل الاعتماد الخام على النموذج

البرومبت يُحقَن بصفحة التوثيق الرسمية لكود الخطأ (من 1.1) ومقتطف الكود فقط، مع تعليمة صارمة: «أعد الصياغة ولا تضف معلومات من خارج المصدر». هذا تحويل منهجي من «اسأل LLM» إلى **نظام مقيَّد قابل للتقييم** — ويعطي الطبقة الثالثة عمقًا بحثيًا حقيقيًا.

### 3.2 تلميحات تربوية متدرجة (Progressive Hints)

بدل إعطاء الحل كاملًا: المستوى 1 إعادة صياغة الخطأ، المستوى 2 إشارة إلى السطر والمفهوم، المستوى 3 مثال مشابه، والمستوى الأخير فقط الإصلاح المقترح. مبدأ معروف في تعليم البرمجة (scaffolding) ويميز مشروعك عن «chatbot يحل الواجب».

### 3.3 تخزين مؤقت للشروحات (Cache)

الأخطاء الشائعة تتكرر؛ تخزين الشرح حسب (كود الخطأ + بصمة السياق) يخفض التكلفة والزمن ويجعل العرض الحي غير مرهون بسرعة الـ API.

### 3.4 دعم نماذج عربية محلية + مقارنة تجريبية

تشغيل الشارح على نموذج سحابي وعلى نموذج عربي مفتوح محلي (مثل Jais أو AceGPT عبر Ollama) ومقارنة: دقة الشرح، سلامة اللغة العربية، زمن الاستجابة، الخصوصية. هذه المقارنة وحدها قسم تجريبي ممتاز في التقرير.

### 3.5 حارس جودة للمخرجات (Guardrails)

فحص آلي بسيط لمخرجات LLM قبل عرضها: أنها بالعربية، لا تتجاوز طولًا محددًا، لا تحتوي كودًا يُنفَّذ تلقائيًا، وتذكر رقم السطر الصحيح. يُسجَّل معدل الرفض كمقياس إضافي.

## 4. طبقة جديدة: البعد التعليمي (Learning Layer)

هذه الطبقة تحوّل المنصة من «أداة» إلى «بيئة تعلم» — وهي أسهل الطبقات تنفيذًا لأنها تُبنى فوق ما سبق.

### 4.1 مسار دروس تفاعلي داخل محرر الويب

8–10 دروس قصيرة (المتغيرات ← الشروط ← الحلقات ← الدوال)، كل درس: شرح + تمرين + **مصحّح آلي** (تشغيل كود الطالب على حالات اختبار خفية في WASM داخل المتصفح — دون خادم). هذا هو السيناريو الذي تُقاس عليه دراسة المستخدمين (انظر 7).

### 4.2 متتبّع تنفيذ مرئي (Execution Visualizer)

عرض خطوة-بخطوة لقيم المتغيرات ومسار التنفيذ فوق المفسر (على غرار Python Tutor). بديل أخف من منقّح DAP الكامل وأثره التعليمي أكبر.

### 4.3 توثيق ثنائي اللغة مولَّد آليًا

تعليقات توثيق (`## يحسب مضروب العدد`) يستخرجها مولّد `عر وثّق` إلى موقع توثيق ثابت. يوفر محتوى RAG إضافيًا لطبقة الذكاء الاصطناعي.

## 5. طبقة جديدة: الجودة الهندسية (تُقنع أي ممتحن تقني)

- **تكامل مستمر (GitHub Actions):** كل دفعة تُشغّل اختبارات الوحدة + مجموعة برامج عربية مرجعية (corpus) + اختبارات golden/snapshot لشجرة التحليل، فأي تغيير في الـ grammar يكشف كسره فورًا.
- **Fuzzing للمحلل:** تغذية المحلل بمدخلات عشوائية/مشوّهة (أداة fuzz المدمجة في Tree-sitter) للتحقق أنه لا ينهار أبدًا بل يُصدر خطأ تحليل نظيفًا — نقطة متانة نادرة في مشاريع الطلاب.
- **قياسات أداء آلية في CI:** تشغيل benchmarks (المفسر مقابل WASM) تلقائيًا وتخزين النتائج، فجدول التقييم في التقرير يتولد من بيانات حقيقية قابلة لإعادة الإنتاج.
- **سجل قرارات معمارية (ADRs):** ملف قصير لكل قرار كبير (لماذا Rust؟ لماذا WAT قبل LLVM؟ سياسة الأرقام؟). يُظهر نضجًا هندسيًا ويكتب نصف فصل «المنهجية» في التقرير مجانًا.
- **نشر مفتوح المصدر** برخصة واضحة (MIT/Apache-2.0) مع `README` ثنائي اللغة وإصدارات مرقمة (SemVer) — يحوّل المشروع من «تسليم جامعي» إلى مشروع حي يُستشهد به.

---

## 6. طبقة جديدة: الأمان وقيود التشغيل

تشغيل كود المستخدمين (في الساحة والدروس) يستلزم:

- **حدود موارد في المتصفح:** سقف ذاكرة لوحدة WASM، ومهلة زمنية تقطع الحلقات اللانهائية (تشغيل في Web Worker يُنهى عند تجاوز المهلة، أو عدّاد وقود/fuel في المفسر).
- **لا تنفيذ تلقائيًا لمخرجات LLM** (مثبت أصلًا في التصميم) + تعقيم أي عرض HTML لمخرجات البرامج.
- فصل تشغيل الكود عن واجهة المحرر حتى لا يجمّد كودُ الطالب الصفحةَ كلها.

قسم «الأمان» القصير هذا في التقرير يميّزك؛ معظم مشاريع اللغات التعليمية تتجاهله كليًا.

---

## 7. طبقة جديدة: إتاحة الوصول وتجربة الاستخدام (Accessibility/UX)

- **خط برمجي عربي:** استخدام خط عربي مناسب للكود مثل Kawkab Mono مع محاذاة سليمة للأرقام والرموز — تفصيلة صغيرة ترفع جودة كل لقطة شاشة في التقرير والعرض.
- **تبديل عرض الأرقام:** خيار واجهة يعرض الأرقام شرقية أو غربية (التمثيل الداخلي موحّد أصلًا حسب قرار النواة).
- **دعم قارئات الشاشة** في محرر الويب (ARIA)، ووضع تباين عالٍ، وأحجام خط قابلة للتكبير.
- **قياس قابلية الاستخدام رسميًا:** استبيان **SUS** (System Usability Scale) ضمن دراسة المستخدمين — يعطي رقمًا معياريًا قابلًا للمقارنة عالميًا بدل انطباعات عامة.

## 8. تعزيز طبقة التقييم (مقاييس إضافية)

| المقياس الجديد | الطريقة | ما يضيفه |
|---|---|---|
| زمن استجابة LSP | قياس p50/p95 للإكمال والتشخيص على ملفات بأحجام متدرجة | «أدوات حقيقية» تعني أيضًا سرعة ملموسة |
| قابلية الاستخدام (SUS) | استبيان معياري بعد جلسة الدروس التفاعلية | رقم معياري عالمي بدل انطباعات |
| مقارنة مباشرة مع Alif | نفس 5 برامج تُكتب باللغتين: عدد الأسطر، وضوح الأخطاء، التشغيل في المتصفح | تموضع تنافسي مدعوم بالدليل |
| سحابي مقابل محلي (LLM) | نفس مجموعة الأخطاء على النموذجين؛ تقييم بشري مزدوج التعمية لجودة الشرح | عمق بحثي لطبقة AI |
| متانة المحلل | نسبة مدخلات الـ fuzzing التي عولجت بخطأ نظيف دون انهيار | جودة هندسية قابلة للقياس |
| معدل رفض الحارس | نسبة مخرجات LLM المرفوضة آليًا (من 3.5) | وعي بحدود الذكاء الاصطناعي |

## 9. هيكلة المستودع المقترحة (Monorepo)

```
Final-project/
├── docs/                  # وثائق التصميم وقرارات ADR والتقرير
├── grammar/               # tree-sitter-arabic: grammar.js + اختبارات corpus
├── interpreter/           # المفسر + REPL (Rust)
├── compiler-wasm/         # مولّد WAT → WASM
├── stdlib/                # المكتبة القياسية العربية
├── lsp-server/            # خادم LSP (+ لاحقًا DAP)
├── editors/
│   ├── vscode/            # إضافة VS Code
│   └── web/               # محرر الويب (CodeMirror + طبقة BiDi + الساحة)
├── ai-explainer/          # شارح الأخطاء: RAG + برومبتات + حارس الجودة + cache
├── learn/                 # الدروس التفاعلية + المصحح الآلي
├── benchmarks/            # قياسات الأداء (تُشغَّل في CI)
└── evaluation/            # أدوات الدراسة: استبيانات، سكربتات تحليل، نتائج
```

## 10. ترتيب الأولويات المحدَّث (MoSCoW)

حتى لا تُغرق الإضافاتُ الخطةَ، تُدمج في الجدول الزمني القائم هكذا:

- **Must (ضمن MVP – لا تفاوض):** النواة + المفسر + REPL + أكواد الأخطاء الموثقة + سياسة Unicode + LSP أساسي + محرر RTL صحيح + CI باختبارات corpus.
- **Should (مخطط لها في الفصل الثاني):** WASM في المتصفح + الساحة بروابط المشاركة + شارح الأخطاء بنهج RAG مع الحارس + المنسّق + SUS ومقاييس التقييم الإضافية + حدود الموارد.
- **Could (إن سمح الوقت):** التلميحات المتدرجة، المتتبّع المرئي، المقارنة سحابي/محلي، Linter موسع، مدير الحزم، التوثيق المولَّد.
- **Won't (ما بعد التخرج — تُذكر كخارطة مستقبل):** LLVM backend كامل، منقّح DAP كامل، الاستضافة الذاتية (self-hosting)، تطبيق جوال.

ذكر بند «Won't» صراحةً أمام اللجنة نقطة قوة: يثبت أنك تعرف حدود النطاق ولم تتجاهلها.

## 11. مخاطر إضافية وتخفيفها

| المخاطرة | التخفيف |
|---|---|
| تضخم النطاق بسبب الإضافات نفسها | الالتزام الصارم بتصنيف MoSCoW أعلاه؛ أي ميزة جديدة تدخل «Could» افتراضيًا |
| كود الطالب يجمّد المتصفح في الدروس | التشغيل في Web Worker بمهلة إنهاء إجبارية (من 6) |

| تكلفة/انقطاع API الخاص بـ LLM أثناء العرض | الـ cache (من 3.3) + نموذج محلي احتياطي عبر Ollama |
| كسر الـ grammar عند كل توسعة | اختبارات golden/snapshot في CI تكشف أي انحراف فورًا |

## 12. خلاصة الإضافات في سطر واحد لكل طبقة

1. **النواة:** أكواد أخطاء موثقة + سياسة Unicode صريحة + REPL + مكتبة قياسية — تجعل اللغة «قابلة للاستخدام» لا «قابلة للعرض» فقط.
2. **الأدوات:** منسّق + ساحة بروابط مشاركة + حزمة VS Code منشورة — منتجات ملموسة يلمسها أي ممتحن.
3. **الذكاء الاصطناعي:** RAG على توثيقك + تلميحات متدرجة + حارس جودة — من «سؤال chatbot» إلى نظام مقيَّد قابل للقياس.
4. **التعليم:** دروس بمصحح آلي + متتبّع مرئي — تحويل المنصة إلى بيئة تعلم تُجرى عليها الدراسة.
5. **الجودة:** CI + fuzzing + benchmarks + ADRs — متانة هندسية نادرة في مشاريع التخرج.
6. **الأمان والإتاحة:** حدود موارد + SUS + خط عربي برمجي — اكتمال احترافي يغطي الزوايا التي يسأل عنها الممتحنون عادة.
